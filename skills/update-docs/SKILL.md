# Update Docs — به‌روزرسانی مستندات

## When to use — چه زمانی

- مدل، پروایدر، endpoint، متغیر محیطی یا اسکریپت `npm` تازه‌ای اضافه شده.
- عددی در سند کهنه شده (تعداد مدل‌ها، حجم بدنه، ضرب‌العجل، نسخهٔ Node).
- سند خراب شده (بایت NUL، نیمه‌نوشته، جدول شکسته).
- مهارت تازه‌ای در `skills/` اضافه کرده‌اید.

---

## Which document says what — هر سند برای چه کاری است

| سند | مخاطب | محتوا |
|---|---|---|
| `README.md` | کاربر/توسعه‌دهندهٔ تازه + موتور جست‌وجو | معرفی، نصب/اجرا، endpointها، مدل‌ها، کلیدها، معماری، عیب‌یابی |
| `HANDOFF.md` | توسعه‌دهندهٔ بعدی (تحویل پروژه) | وضعیت جاری، قواعد طلایی، نقشهٔ فایل، چک‌لیست راستی‌آزمایی |
| `AI-GUIDE.md` | دستیار هوش مصنوعی | راهنمای عمیق لایه‌ها + قراردادها + playbook |
| `skills/*/SKILL.md` | دستیار/توسعه‌دهنده هنگام کار | دفترچهٔ عملیات هر تغییر (این پوشه) |
| `worklog.md` | تاریخچه | رویدادنامهٔ تغییرات (به‌همین سادگی اضافه کنید) |
| `docs/providers.schema.json` | ویرایشگر/CI | اسکیمای رجیستری |
| `download/` | انتشار/آفلاین | کپی `.md`ها + خروجی HTML/PDF + فونت‌ها |

## The GENERATED blocks — بلوک‌های تولیدی

هر جا این نشان‌ها را دیدید، محتوای بینشان **دست‌نویس نیست**:

```markdown
<!-- GENERATED:models -->
…محتوایی که scripts/docs-sync.mjs می‌سازد…
<!-- /GENERATED:models -->
```

بلوک‌های موجود (همه در `scripts/docs-sync.mjs` تعریف شده‌اند):

| id | چه تولید می‌کند | منبع حقیقت |
|---|---|---|
| `models` | جدول مدل‌ها (فارسی) | `providers.json` |
| `models-en` | همان جدول به انگلیسی | `providers.json` |
| `providers` | جدول پروایدرها (id/نام/سایت/شکل/مدل‌ها) | `providers.json` |
| `groups` | جدول گروه‌های پیکر مدل + آیکن | `providers.json` |
| `endpoints` | جدول endpointها (مسیر/متد/کاربرد) | روت‌های `src/app` + روتر `app.js` |
| `env` | جدول متغیرهای محیطی | کد (`process.env.*`) |
| `keys` | کلیدهای API فعلی | `api-keys.json` |
| `stats` | آمار کلیدی (تعداد/حجم/ضرب‌العجل) | رجیستری + کد |
| `counts` | شمارش‌های کوتاه (برای متن) | رجیستری |
| `scripts` | جدول `npm run …` | `package.json` |
| `skills` | جدول مهارت‌ها + توضیحشان | فولدر `skills/` (از front matter) |

### فرمان‌ها

```bash
npm run docs:sync                       # بازنویسی بلوک‌ها + کپی به download/
npm run docs:check                      # فقط بررسی (exit 1 اگر سند عقب باشد)
node scripts/docs-sync.mjs --print models,endpoints   # پیش‌نمایش بدون نوشتن
node scripts/docs-sync.mjs --no-copy                  # کپی download/ انجام نشود
```

`npm run verify` هم `docs:check` را صدا می‌زند، هم همگامی `download/` را
می‌سنجد و هم سلامت رمزگذاری سند (بایت NUL/UTF-16) را.

### افزودن بلوک تازه

1. در `scripts/docs-sync.mjs` یک generator اضافه کنید:
   ```js
   /** توضیح یک‌خطی */
   'my-block'() {
     const rows = allModels.map((m) => `| \`${m.id}\` | ${m.name} |`);
     return ['| ستون | ستون |', '|---|---|', ...rows].join('\n');
   },
   ```
2. در سند، جایی که می‌خواهید، نشان‌ها را بگذارید:
   ```markdown
   <!-- GENERATED:my-block -->
   <!-- /GENERATED:my-block -->
   ```
3. `npm run docs:sync` و بعد `npm run verify`.

> نام بلوک باید `[a-z0-9-]+` باشد (الگوی regex در `syncFile`).

## Style contract — قرارداد سبک

1. **دوزبانه:** سرآیندها و برچسب‌های جدول انگلیسی، متن و توضیح فارسی.
   الگو: `## Overview | معرفی`. این قرارداد را عوض نکنید (کاربر انتخاب کرده).
2. **RTL در markdown نه، در HTML بله:** فایل‌های `.md` ساده بمانند؛ فقط
   `download/docs/*.html` جهت راست‌به‌چپ و فونت وزیرمتن دارند.
3. **داده در جدول، نه در متن:** هر عدد/فهرست که ممکن است عوض شود را یا در
   بلوک GENERATED بگذارید یا در جدول؛ داخل پاراگراف ننویسید.
4. **کلیدهای API واقعی در سند می‌مانند** (تصمیم صریح مالک پروژه — اپ
   محلی/شخصی است). اگر روزی ریپو عمومی و کلیدها حساس شدند، بلوک `keys` را از
   سند بردارید و فقط `GET /api/keys` را معرفی کنید.
5. **بدون بایت NUL / UTF-16:** اگر سندی را با ابزار بیرونی ویرایش کردید، بعدش
   `npm run verify` بگیرید (این اشکال یک‌بار README را خراب کرد).
6. **پایان فایل با خط جدید** و بدون فاصلهٔ اضافه در انتهای خطوط.
7. **فارسی‌نویسی:** نیم‌فاصله (`می‌شود` نه `می شود`)، نقطه‌گذاری لاتین در کد،
   اعداد در متن فارسی می‌توانند فارسی باشند ولی در جدول/کد لاتین.

## download/ — کپی انتشار

```
download/README.md · HANDOFF.md · AI-GUIDE.md   ← کپی مستقیم (docs:sync)
download/docs/SmartChat-{README,HANDOFF,AIGUIDE}.{html,pdf}  ← خروجی بیرونی
download/docs/assets/fonts/                     ← فونت وزیرمتن برای HTML/PDF
```

- `.md`ها خودکار کپی می‌شوند؛ `verify` تفاوت را گزارش می‌کند.
- `HTML/PDF`ها با ابزار بیرونی (markdown→html/pdf) ساخته شده‌اند و با
  `docs:sync` به‌روز **نمی‌شوند**. بعد از تغییر بزرگ سند، اگر انتشار مهم است،
  دوباره بسازید و سپس:
  ```bash
  python3 scripts/postprocess_pdfs.py    # شمارهٔ صفحه + متادیتا + بررسی U+FFFD
  ```
  (نیاز به `pymupdf` دارد.)

## Adding a skill — افزودن مهارت تازه

1. فولدر `skills/<name>/` و فایل `SKILL.md` با front matter:
   ```markdown
   ---
   name: <name>
   description: یک جمله — چه کاری و کی استفاده شود (این جمله در جدول README و بلوک GENERATED:skills می‌آید)
   ---
   ```
2. بخش‌ها: `When to use` · `Steps` · `Verify` · `Pitfalls` · `Related`.
3. در جدول § ۱ `skills/README.md` یک سطر اضافه کنید.
4. `npm run docs:sync` (بلوک `skills` در README تازه می‌شود) و `npm run verify`
   (مسیرها/فرمان‌های `npm run`/پیوندهای داخل مهارت را می‌سنجد).

## Verify — چک‌لیست

- [ ] `npm run docs:check` بدون خطا (بلوک‌ها به‌روزند)
- [ ] `npm run verify` → بخش «سندها» سبز + بخش «ارجاع‌های مستندات» سبز
- [ ] `download/README.md` با `README.md` یکی است
- [ ] هر عددی که دستی نوشتید با واقعیت کد می‌خواند (تعداد مدل‌ها، حجم، timeout)
- [ ] لینک‌های داخلی کار می‌کنند (`skills/…`، `scripts/…`، `docs/…`)
- [ ] `git diff` سند را نشان می‌دهد (نه یک فایل باینری/خراب)

---

## Pitfalls — دام‌ها

| دام | نتیجه | راه‌حل |
|---|---|---|
| دستی داخل بلوک GENERATED نوشتید | دفعهٔ بعد `docs:sync` رویش می‌نویسد | متن آزاد را **بیرون** بلوک بگذارید |
| نشان بستن (`/GENERATED:x`) را پاک کردید | کل بلوک از سند می‌افتد | همیشه جفت نشان‌ها را نگه دارید |
| `download/` را دستی ویرایش کردید | `docs:sync` بازنویسی‌اش می‌کند | فقط ریشه را ویرایش کنید |
| عدد دستی در پاراگراف | با اولین تغییر مدل کهنه می‌شود | بلوک `counts`/`stats` |
| کپی‌کردن سند از خروجی UTF-16 | بایت NUL و سندِ خراب | `verify` می‌گیردش؛ با ویرایشگر متن ساده کار کنید |
| معرفی اسکریپتِ `npm` که وجود ندارد | `verify` خطا می‌دهد | اول اسکریپت را در `package.json` اضافه کنید (یا نام درست را بنویسید) |
| مسیر `src/lib/foo.ts` که عوض شده | `verify` خطا می‌دهد | بعد از refactor، سند را grep کنید |
